# 《钩子搬运工》首轮原型与试玩计划

> 2026-09-17 · 三个房间已实现，技术验证完成，尚未做五人玩法访谈。依据 [主设计文档](POKI_GAME_DESIGN.md)，当前证据见 [试玩记录](HOOK_MOVER_PLAYTEST.md)。  
> 目的：用约 20–35 小时的投入判断核心动作值不值得继续，而非先做完整游戏。
> 首次真人反馈：手机可通三关，但目标识别和核心乐趣未通过。目标提示已修正，暂停新增关卡；后续以试玩记录中的调整为准。

## 1. 原型必须回答什么

“货物可以先帮忙、再交付”是否让玩家主动改变操作计划？仅仅能拉箱子、能碰撞、能过关，不足以通过。

初版只做单指按住牵引、松手脱钩。点空地移动作为失败后的对照方案，不提前并行开发。

## 2. 只包含这些内容

| 项目 | 上限 |
| --- | --- |
| 玩家 | 一台圆形搬运机器人 |
| 物体 | 轻箱、重箱、固定锚点；每关最多 3 件货物 |
| 场景 | 墙、开阔通道、一个装货区；第三关加入一组重型压板门 |
| 连接 | 同时只有一根直线钩索，不绕柱、不穿墙 |
| 关卡 | 3 个灰盒房间，不制作正式场景美术 |
| 恢复 | 撤销本关有效发钩、重置、暂停；后台恢复后不残留按住输入 |
| 结算 | 所有必需货物入区并停稳后，点装车完成 |
| 设备 | 一台实际手机与一台桌面浏览器；不把浏览器触控模拟当成手机实测 |

不加入货币、升级、敌人、软墙、传送带、易损货物、皮肤、地图编辑器界面或广告。正式素材和平台接入安排到完整小样阶段，平台约束从现在保留。

## 3. 三个房间及其用途

### 房间 A：第一次停放

开阔空间，一只轻箱和数个固定锚点。轻箱是唯一必需交付物。装货区靠近初始人物，第一次拉轻箱即可完成停放，随后点装车结束本关。

用一次简短手势提示按住与松手。固定点前有减速；货物与玩家的相对移动能直接看懂。没有死亡、限时或必须完美停住的要求。

验收重点：能否无口头帮助选中货物、松手停放并装车；是否误把固定点认作必需交付物。

### 房间 B：换边与转角

加入一只靠近装货区的重箱和一段宽障碍。重箱仅需局部调整，轻货需要从障碍另一侧搬来；两件都要交付。先在开阔处感受拉重箱与固定点的区别，再借固定点换到轻货另一侧。两条路线可用，关键转角留有足够宽的停靠空间。

验收重点：玩家能否预测重箱和固定点会让自己移动更多；从“知道想怎么搬”到“把人物放到对应位置”，不能成为主要操作负担。如果一个很简单的转角就需要连续精调数次锚点，应先改场景或控制。

### 房间 C：先用，后搬

采用主文档的压板门委托：轻货在北侧，重箱在南侧，中间短通道受压板控制，外侧有始终可走的宽长路。

重箱、压板和装货区相邻，重箱的移动限于局部，不要求反复退回锚点来磨出搬运距离。门被人物或货物占据时暂缓关闭；钩索不推挤第三件物体，门关闭后隔断连接则脱钩。

开场只说明“把两件货装好”。压板、连线与门的视觉关系明确，不直接告诉玩家先搬哪件。重箱进入装货区后还能取出来，关闭门也不切断固定回程路线。

至少由开发者验证两条不同搬运顺序都能稳定完成，不要求像素级角度或精确时机。试玩观察有没有玩家主动发现重箱的双重用途。

## 4. 输入和状态约定

1. 按下有效目标前保存一次完整快照；无效点击不消耗操作次数，也不新增撤销记录。
2. 按住时保持同一目标。松开、pointercancel、页面失焦、暂停和方向切换都会停止牵引。
3. 快照包含物体位置与速度、机关状态、交付状态、操作计数及影响后续结果的状态，不仅保存人物坐标。
4. 撤销恢复后先保持暂停，下一次有效操作再继续，避免刚恢复就被惯性带走。已装车结算后不能用撤销重复领奖。
5. 装货只按当前实体位置判定，进入区域不删除物体。未停稳、还在牵引或货物尚未完全入区时不能装车。
6. 本轮只存已完成房间与设置；刷新后当前房间从头开始，界面明确说明。关内快照持久化留给完整小样，避免把调档工程变成核心原型前置条件。

## 5. 必须先排除的操作故障

| 故障 | 验证或修正 |
| --- | --- |
| 手指点 A 却钩了 B | 在实际手机记录误选；调整目标间隔、描边、命中范围和遮挡优先级 |
| 穿墙钩、高速穿箱 | 检查可视连接和碰撞；限制速度，必要时加强碰撞检测 |
| 关键固定点被货物遮住 | 改锚点位置、拓宽回程路线；不把可撤销当作不修地图的理由 |
| 重箱进装货区后永远堵路 | 装货区宽松布局，货物可继续移动；不提前吞货或锁定 |
| 重箱需要反复回位才能拖过场地 | 把机关和交付点放近，由轻货承担主要运输；无法消除的重复搬运视为玩法失败 |
| 暂停恢复后仍在拉 | 清空活动指针与牵引动作，要求新的按下才开始 |
| 撤销导致压板、门或交付清单不一致 | 从同一场景状态重算派生结果，检查完整状态恢复 |
| 低帧率时牵引结果大变 | 固定模拟步长，检查相同输入在不同帧率下是否产生近似结果 |

规则测试覆盖牵引、碰撞边界、交付和完整状态恢复；当前技术结果记录在试玩记录中。体验和真实手机手感仍依靠玩家操作观察，不以自动化通关代替。

## 6. 第一轮怎样观察

先让开发者本人实际手机玩，再找 5 位未听过方案的人。不给口头指挥，每人最多观察 10–15 分钟，可以随时结束。录制前征得对方同意；不把录像或个人资料发到外部服务。

记录以下原始事实：首次有效牵引时间；误钩或取消次数；停顿原因；换位与实际搬运的大致时间；使用的路线；主动撤销的原因；是否主动开始下一关。

试玩后只问具体行为：刚才为什么先动这个箱子？哪次结果出乎意料？有没有想做却难以操作的动作？最后才问是否愿意再试一个房间。观察比口头说“挺好”更有用。

以下门槛是本项目的内部决策线，小样本不代表市场统计，也不是 Poki 的通过标准。

| 要验证的事 | 暂定继续信号 | 未达到时先做什么 |
| --- | --- | --- |
| 能独立上手 | 至少 4/5 在 60 秒内无口头帮助完成一次牵引与停放 | 改命中和第一屏，不添加更多关卡 |
| 理解轻重 | 至少 4/5 能正确解释一次“人移动更多”的结果 | 调相对速度和反馈，检查质量规则是否过于细碎 |
| 货物有工具用途 | 至少 3/5 在房间 C 主动尝试压板或合理利用重箱位置 | 检查机关可读性；若仍只照路线搬，核心差异不足 |
| 不同方法值得使用 | 5 人中出现两种成功顺序，并能说出选择原因 | 重新平衡路线成本，删除假选择 |
| 想继续尝试 | 至少 3/5 主动进入下一个房间或重试自己想改善的方法 | 检查操作疲劳和委托变化，不加数值奖励掩盖 |
| 换位不过度占用时间 | 若至少 3/5 的多数操作时间都在艰难摆正人物，视为失败 | 制作点空地移动的单独对照输入 |

完成房间后由开发者强行让人玩下一关，不计作“主动继续”。因为误钩而重复一关，不计作“愿意重玩”。所有门槛配合观察解释，不能只看人数打勾。

## 7. 投入和决策

| 工作包 | 原型预算 |
| --- | --- |
| 可控牵引、质量差、简单碰撞 | 6–10 小时 |
| 手机输入、目标反馈、暂停和撤销 | 5–8 小时 |
| 三个房间、装货与简单引导 | 5–8 小时 |
| 实际设备与第一轮观察、记录 | 4–9 小时 |
| 合计 | 20–35 小时 |

预算用于暴露风险；超时先停下来解释原因，不自动吞掉后续几个月。第一轮后若要继续实验，第二轮最多再安排约 10–15 小时：只修一至两个观察到的问题，或专门对照测试点空地移动，两者不要一起扩做。

第一轮后可选择继续小样、进入第二轮或撤回方向。第二轮结束只作以下判断：

- **继续：**操作流畅，玩家主动复用物体，两条方法都有人选择；进入 6 份委托的完整小样。
- **撤回方向：**操作已清楚，玩家仍只觉得重复搬箱子；停止扩内容，回到候选筛选。

如果第二轮仍未给出答案，就记录为未通过，不把后续改输入隐含成免费第三轮。确需新的实验时，重新明确要验证的假设、预计投入和停止条件。

每轮输出一页事实记录：版本、设备、玩家数、发生了什么、改什么、是否继续。原型通过后再写生产任务，不提前把全年工作拆成实现清单。

# 《钩子搬运工》实现与验证记录

日期：2026-09-17。状态：三房间玩法原型，可试玩；尚未通过五人玩法门槛或 Poki 平台测试。

## 已实现

- 手机按住目标牵引、松手释放；桌面鼠标同样操作。处理指针取消、指针捕获丢失、失焦和切后台。
- 轻货、重货、固定锚点采用同一质量比例规则；固定步长、受控速度、平面碰撞。
- 三个完整房间、压板门、第三关两条可通路线。
- 货物在装货区保持实体，可再取出；停稳并全部就位后装车。
- 完整撤销、重置、暂停、音效、通关保存和再次选择已解锁房间。
- 失焦暂停；存储不可用仍可玩；刷新当前房间会重开，并在暂停面板说明。
- 竖屏、横屏、桌面 HUD 和场地缩放；原拖车页面保留在 /convoy。

参考了 LastCar 的指针生命周期与安全区处理、survios2 的规则/场景/UI 分层。两个参考项目未修改，也未复制其平台 SDK 或美术资源。沿用本仓库 Phaser 3，无引擎版本升级。

## 为可玩性做的调整

重箱只做局部移动。第三关的重箱初始就在装货区，玩家需要考虑是否先借出来压门；这直接体现“交付物也能作为工具”。

第三关补了门南侧的固定点。压板路线由此可以连续按住目标完成，不要求在 0.35 秒的特定时机松手。固定点是可靠的回程工具，货物随时可撤销复位。

程序化精灵和简化碰撞优先保证可读性。没有加入额外机关、数值成长、精确计时奖励或付费撤销。

包含三关真实牵引通关、第三关压板与绕行两条路线、暂停与重新输入、撤销恢复完整物体状态、墙体遮挡、10 FPS 防穿透、门洞有货/有人防夹、已交付货取出再使用，以及 120/60/20/10 FPS 路线一致性。

路线测试通过 beginPull / update / endPull 操作正常状态，不瞬移实体，也不直接设置胜利。开发者验证解法为 A 一钩、B 六钩、C 压板七钩、C 绕路九钩；这不是玩家评级要求。

`node --test game/simulation.test.mjs`：旧原型 12/12 回归测试通过。

额外验证 touchCancel 结束牵引、浏览器存储抛异常后的降级，以及以下尺寸切换时画布完整处于场地内：390×844、375×667、844×390、568×320、1365×900。

本地截图和临时浏览器脚本位于 outputs/，不随站点发布。浏览器模拟不能证明实际手机触感和性能。

## 首次真人反馈与范围调整（2026-09-17）

用户在手机上通过三关。第二关首次误以为只需交付轻箱，以为不能装车是程序故障；第二次才理解重箱也要交付。反馈证明原有“两件货”和计数不足以说明目标。

本轮修正：逐件列出轻箱、重箱与就位状态；场内货物显示同名标签；装车按钮说明还缺哪件；第三关结尾明确当前原型只有三关。规则和关卡不扩展。

修正验证：11 项规则测试、类型检查、定向 lint 和生产构建通过。浏览器真实触控完成轻箱已送达而重箱仍未送达的状态，检查清单、缺货提示与装车禁用；再交付重箱后可装车。五种视口的画布边界检查通过，无页面运行异常。

更关键的反馈是“没什么感觉，感觉只要点一点就能过关”，以及更喜欢王者荣耀。这说明当前原型尚未证明核心乐趣，不能以完成三关作为继续扩关的依据，也不能据此认定年龄是原因。

暂停新增搬运关卡。用户进一步确认，王者荣耀最吸引自己的是“人与人的对抗：猜对手、队友配合、输赢和段位”。因此不能把需求简单解释为更强的打击感或更多单人战斗。

下一轮候选改为小规模真人对抗：先用一个可邀请朋友加入的 1 对 1 争夺目标场景，验证骗技能、抢夺与撤退是否值得立即再玩；团队配合可在此之后单独验证。联网对局、匹配与段位均尚未实现或授权进入开发，不能将机器人对局冒称真人。已有三关保留用于回看，不继续靠增加房间数量弥补核心反馈。
